## 2. これからの構成

役割を2つに分けます。

| | 役割 |
| --- | --- |
| **GitHub Pages** | アプリ共有システム（画面）の公開 |

## 3. Supabaseに保存する予定のもの

### apps
アプリ情報。現在の `data/apps.js` の内容にあたる。

| 列（想定） | 内容 |
| --- | --- |
| id | アプリID（`shift` など。コメントの紐づけに使う） |
| name | アプリ名 |
| description | 説明 |
| version | 現在のバージョン |
| updated_at | 最終更新日 |
| status | 状態（公開中 / 確認中 / 準備中） |
| path | アプリ本体の場所 |

### comments
アプリごとのコメント。現在 localStorage に入っているもの。

| 列（想定） | 内容 |
| --- | --- |
| id | コメントID |
| app_id | どのアプリへのコメントか |
| author | 投稿者 |
| body | 本文 |
| created_at | 日時 |
| status | 状態（未対応 / 確認中 / 対応済み） |

※ 試作版のコメントもこの6項目で保存しているため、形はそのまま移せます。

### app_versions
バージョンの履歴。現在の `changelog` にあたる。

| 列（想定） | 内容 |
| --- | --- |
| id | 履歴ID |
| app_id | どのアプリか |
| version | バージョン |
| changelog | 更新内容 |
| published_at | 公開日時 |

### profiles
ユーザー情報。現在は表示名を自分で入力しているが、これを置き換える。

| 列（想定） | 内容 |
| --- | --- |
| id | ユーザーID |
| name | 表示名 |
| role | 権限（管理者 / 一般 / 閲覧のみ） |

## 4. 追加予定の機能

### 複数端末リアルタイム共有
- コメントを Supabase に保存し、全端末で同じ内容が見えるようにする
- **Supabase Realtime** を使い、誰かの書き込みを他の端末の画面へすぐ反映する
- 未読の件数表示

### ログイン
- 職員が自分の名前でログインする
- 現在は表示名を自分で入力しているが、これを `profiles` に置き換える

### 権限管理
- 管理者 … アプリの登録・更新・削除、コメントの状態変更
- 一般 … アプリの閲覧、コメントの投稿
- 閲覧のみ … コメントの閲覧のみ
- Supabase側の行レベルの制限（RLS）と合わせる

### ファイルアップロード
- コメントに画像（不具合画面のスクリーンショット）を添付する
- 「ファイル」タブから、最新版 / 過去バージョン / PDF資料 / 画像 / 説明資料 を登録する
  ※ 区分の定義は `data/apps.js` の `FILE_CATEGORIES`、登録先は各アプリの `files` 配列（現在は空）
  ※ 1件の形 `{ id, category, label, version, updatedAt, path }`
- 保存先は Supabase Storage を想定

### 本物のアプリ登録
- `apps/` 配下に各アプリを配置する（GitHub Pagesから一緒に配信される）
- `data/apps.js`（将来は `apps` テーブル）の `path` を埋めると「アプリを開く」が有効になる
- バージョンと更新内容を `app_versions` に記録する

### コメントまわりの改善
- コメントの状態（未対応 / 確認中 / 対応済み）を画面から切り替える
  ※ データ構造は試作版の時点で用意済み（`comment.status`）
- コメントの編集・削除
- 状態での絞り込み表示
- アプリごとの未対応件数の表示

## 5. 移行の進め方（案）

1. **画面の確定** … 試作版を実際に使ってもらい、表示項目と操作を固める ← 現在ここ
2. **公開** … GitHubへ上げ、GitHub Pages で開ける状態にする（保存先はまだ localStorage）
3. **コメントの共有** … Supabase にテーブルを作り、`CommentStore` の中身を Supabase 呼び出しに差し替える
4. **リアルタイム反映** … Supabase Realtime を購読し、他の端末の書き込みを画面へ反映する
5. **ログインと権限** … `profiles` を作り、投稿者名をアカウントに置き換える
6. **アプリ本体とファイルの登録** … `apps/` への配置と Storage へのアップロードに対応する

## 6. Supabase接続時に変更するファイル

| ファイル | 変更の内容 |
| --- | --- |
| `js/chat.js` | `CommentStore`（list / count / add / setStatus）の中身を Supabase 呼び出しに変える。**ここが中心** |

| `data/apps.js` | 固定データをやめ、取得できないときの予備データにする |
| `js/app.js` | ログイン状態の判定と、Realtime の購読開始・終了を追加する |
| `index.html` | Supabase の読み込みを1行追加する |
| 新規 `js/supabase.js` | 接続設定とクライアント生成をこのファイルにまとめる |

## 7. 実装するときの注意

- 保存処理は `js/chat.js` の `CommentStore` だけを変更すれば差し替えられるようにしておく
- `data/apps.js` のデータ構造は、Supabaseのテーブル定義と揃えておく
- **接続情報（URL・anon key・パスワード・APIキー）をリポジトリに書かない**
  公開リポジトリの場合は誰でも読めるため、設定ファイルは `.gitignore` に入れる
- 画面のパスはすべて相対で書く（GitHub Pages のサブフォルダ公開のため）
- Safari と Chrome の両方で動作を確認する（iPadでの利用が中心のため）
- 絵文字は使用しない。アイコンはシンプルな線画SVGを使う
- 既存アプリ（シフト管理・業務日誌・介護記録ソフト・送迎表など）のファイルは変更しない
