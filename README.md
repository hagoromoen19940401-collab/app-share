# アプリ共有システム（試作版）

社内で作っているWebアプリを複数人で確認し、
アプリごとに意見・不具合・改善案をチャット形式で共有するためのシステムです。

Slackの置き換えを目指すものではありません。
「どのアプリの話なのか」が常にはっきりしている状態で、
最新版をすぐ開いて、その場で気づいた点を書き残せることを目的にしています。

---

## このシステムの目的

1. 複数人で同じWebアプリを確認できる
2. アプリごとに専用の場所がある
3. そのアプリについてチャット形式で意見を書ける
4. 最新版のアプリをすぐ開ける
5. 何がどう更新されたのかが分かる

---

## 現在できること

- 左側のアプリ一覧（共有フォルダ）から、勤務表 / 業務日誌 / 排泄記録 / 送迎表 / 入浴表 を選べる
- アプリ名を押すと、ページ遷移せずに右側の内容だけが切り替わる
- 選択中のアプリが一覧上ではっきり分かる
- 各アプリは「概要 / ファイル / チャット」の3つのタブに分かれている
  - **概要** … バージョン・最終更新日・状態・説明・アプリを開く・今回の更新内容
  - **ファイル** … 最新版 / 過去バージョン / PDF資料 / 画像 / 説明資料 の置き場所（今回は枠のみ）
  - **チャット** … アプリごとのコメント
- タブを切り替えてもページ遷移せず、選択中のアプリはそのまま維持される
- 最後に見ていたアプリとタブは次回開いたときに復元される
- 「アプリを開く」ボタンを押すと、画面内の通知で状況を知らせる
  （今はアプリ本体を登録していないため「このアプリはまだ登録されていません」と表示されます）
- アプリごとに分かれたコメント欄に、投稿者名・本文・投稿日時つきで書き込める
- 表示名は一度入力すると保存され、次回から自動で入る
- コメントは端末内（localStorage）に保存され、Safariを閉じても残る
- コメントは「未対応 / 確認中 / 対応済み」の状態を持てる構造になっている（今回は表示のみ）
- PC・iPad横・iPad縦で崩れず、スマートフォンではアプリ一覧が開閉式になる

### 現在できないこと

- 端末をまたいだ共有（コメントは書き込んだ端末にだけ残ります）
- ログイン、権限管理、ファイルのアップロード
- ファイルの実際の登録（ファイルタブは置き場所の表示のみ）
- 実際のアプリ本体の表示
- コメントの編集・削除、状態の画面からの切り替え

## Safariでの確認方法

### もっとも簡単な方法

1. Finder で `Documents/hito-hito/app-share` を開く
2. `index.html` を右クリックし、「このアプリケーションで開く」→「Safari」を選ぶ

これだけで動作します。

### ローカルサーバーで開く場合（任意）

本番に近い状態で確認したい場合は、ターミナルで次を実行します。

```
cd ~/Documents/hito-hito/app-share
python3 -m http.server 8000
```

Safariで `http://localhost:8000` を開きます。
終了するときはターミナルで `control + C` を押します。

### 確認するとよい点

- 右上の「表示名」に名前を入れてからコメントを送信する
- 勤務表と業務日誌でコメントが混ざらないことを確認する
- 「概要 / ファイル / チャット」を切り替えても、選択中のアプリが変わらないことを確認する
- Safariを閉じて開き直しても、コメントと表示名が残っていることを確認する
- iPadの横向き・縦向きで表示が崩れないことを確認する

> コメントは端末ごとに保存されます。別のiPadやPCには表示されません。
> 他の人にも見えるようにするのは、次のCloudflare対応で行います。

## GitHubで公開する場合（GitHub Pages）

このシステムは HTML / CSS / JavaScript だけで動くため、
ビルド作業なしで GitHub Pages にそのまま置けます。

- ファイルの参照はすべて相対パス（`css/style.css` など）なので、
  `https://<ユーザー名>.github.io/app-share/` のようなサブフォルダ公開でも動きます
- サーバー側の処理や外部サービスへの接続はありません
- `.nojekyll` を置いてあるため、GitHub側で余計な変換が行われません

### 公開したあとの注意

コメントと表示名は **ブラウザごと・URLごと** に保存されます。

- パソコンでファイルを直接開いたときのコメントと、
  GitHub PagesのURLで開いたときのコメントは別のものになります
- 職員それぞれの端末にしか残りません

全員で同じコメントを見るには、次のSupabase対応が必要です。

## 今後の予定（GitHub Pages + Supabase）

役割を2つに分けます。

- **GitHub Pages** … アプリ共有システムそのものの公開
- **Supabase** … 複数人で共有するデータ（アプリ情報・コメント・バージョン・ユーザー）

Supabase Realtime を使い、誰かがコメントを書くと
他の端末の画面にもすぐ表示される状態を目指します。

移行後は、iPadでもPCでも同じコメントが見えるようになります。
詳しくは `docs/DEVELOPMENT.md` を参照してください。

> 現時点ではSupabaseのコードは入っていません。
> URLやキーなどの接続情報も、このリポジトリには含まれていません。
